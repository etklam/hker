# HKER — 常用工具 Section 設計文檔

> **Version**: 0.1 · **Date**: 2026-04-23
> 本文件定義 HKER 新增「常用工具」功能群的產品設計，供 review 後再進入實作。

---

## 1. 背景與目標

HKER 目前首頁已經有主功能入口，但缺少一個適合承載「高頻、輕量、即開即用」小工具的區域。這次新增的功能不應與收藏、市集、家庭待辦混在同一個概念層，而應作為一個獨立的工具群組存在。

本次希望先落地 3 個工具：

1. 辭職 Last Day 計算機
2. 按揭計算機
3. 支票中文英文大寫金額轉換器

### 目標

- 讓首頁能清楚展示「HKER 不只是收藏工具，亦有實用計算工具」
- 提供香港用戶常見、可直接完成任務的實用功能
- 用最小實作成本建立一個可持續擴充的 `/tools` 架構

### 非目標

- 不做帳號綁定、歷史紀錄、收藏常用計算結果
- 不做後端 API 或資料庫儲存
- 不做法律、稅務、銀行政策的完整專業判斷引擎
- 不在第一版支援大量地區差異規則

---

## 2. 資訊架構

### 2.1 導覽層級

建議新增一個新的工具群組，而不是把完整計算器直接塞進首頁。

- 首頁新增 `常用工具` section
- 新增 `/tools` hub 頁
- 每個工具有獨立頁面

### 2.2 建議路由

- `/tools`
- `/tools/resignation-last-day`
- `/tools/mortgage`
- `/tools/cheque-amount`

### 2.3 首頁 Section 的角色

首頁 section 只做導流，不承載完整表單。

原因：

- 避免首頁過長、互動過重
- 工具未來可繼續增加，不影響首頁結構
- 使用者可以先看到工具價值，再進入工具頁完成任務

### 2.4 Navigation 策略

第一版不強制加入 top nav 主導航，先放首頁 section 與 `/tools` hub 即可。

原因：

- 現有 top nav 已有 4 個主項目
- 工具群仍在驗證期，先看使用情況再決定是否升級為一級導航

---

## 3. 共用 UX 原則

3 個工具雖然用途不同，但應共享同一套操作模式。

### 3.1 操作原則

- 進頁即見表單與結果，不把結果藏在下一步
- 使用者每次修改輸入後即時更新結果
- 重要輸出可一眼掃讀，不需要理解公式
- 手機版優先，結果區塊要能自然堆疊

### 3.2 頁面骨架

每個工具頁應包含：

- Hero 區：工具名稱、一句用途說明
- Input Card：輸入欄位
- Result Card：主要結果
- Notes Card：假設、限制、提醒

### 3.3 共用元件模式

- 輸入卡採用現有 `mochi-card`
- 結果數字使用較大的 heading 層級
- 可複製內容要有明確 copy button
- 錯誤狀態以 inline message 顯示，不用 modal

### 3.4 文案原則

- 預設以繁中（香港）語境撰寫
- 用字盡量貼近日常說法，例如「月供」「首期」「遞信日」
- 對規則不確定之處要明示是假設，而不是裝作精準

## 4. 首頁 Section 設計

### 4.1 Section 名稱

建議：

- 中文：`常用工具`
- 英文：`Everyday Tools`

### 4.2 Section 文案方向

副標語建議走「香港日常實用」而非泛用 productivity：

> 幫你快速處理生活上常見的小計算與轉換。

### 4.3 卡片內容

每張卡片顯示：

- 工具 icon
- 工具名稱
- 一句用途摘要
- CTA：`立即使用`

### 4.4 初版工具卡排序

建議順序：

1. 按揭計算機
2. 辭職 Last Day 計算機
3. 支票金額轉換器

原因：

- 按揭工具涵蓋面最廣，也最有機會成為長期流量入口
- 辭職工具有話題性，但使用頻次較低
- 支票工具非常實用，但相對較窄

## 5. `/tools` Hub 頁設計

### 5.1 角色

`/tools` 是工具總覽頁，承接首頁 section 的導流，也作為未來新增工具的聚合頁。

### 5.2 頁面內容

- 頁面標題：`常用工具`
- 簡短說明：聚焦香港生活場景的小工具
- 工具卡 grid
- 可選：`更多工具陸續加入` 的輕提示

### 5.3 不做的東西

- 不做分類篩選
- 不做搜尋
- 不做最近使用

第一版只有 3 個工具，加入這些功能只會增加噪音。

## 6. 工具一：辭職 Last Day 計算機

### 6.1 使用者問題

使用者常見問題不是「通知期是甚麼」，而是：

- 我今日遞信，最後一日返工係幾時？
- 一個月通知是否計到下個月同日？
- 如果合約寫 30 日通知，又應該怎樣計？

### 6.2 定位

這是一個「快速估算工具」，不是法律意見工具。

### 6.3 MVP 輸入

- 遞信日期
- 通知期模式
  - `固定日數`
  - `固定月數`
- 通知期數值
  - 例如 `30`
  - 例如 `1`
- 計算方式說明欄位
  - 當模式為月數時，顯示「以曆月/同日推算」

### 6.4 MVP 輸出

- 最後工作日
- 通知期結束日
- 簡短規則說明

### 6.5 計算規則

第一版只支援兩種清晰模式：

- `按日數計`
  - 以遞信翌日開始計算通知期
  - 到期日前一日或到期日如何表達，文案需清楚統一
- `按月數計`
  - 以同曆日推算，例如 4 月 23 日加 1 個月為 5 月 23 日

### 6.6 重要設計決策

這個工具的最大風險是「規則看似簡單，但其實很易引起爭議」。因此第一版不應把法律細節做得太深。

建議：

- 結果下方固定顯示 disclaimer
- 明確寫出「請以僱傭合約條款及實際人事安排為準」
- 不處理公眾假期、休息日、代通知金、自動順延

### 6.7 邊界情況

- 月尾日期，例如 1 月 31 日加 1 個月
- 閏年 2 月
- 輸入為今日以前或未來日期，皆允許

### 6.8 文案範例

- 主結果：`你的預計最後工作日是 2026 年 5 月 22 日`
- 提示：`此結果只按你輸入的通知期規則估算，並非法律意見。`

## 7. 工具二：按揭計算機

### 7.1 使用者問題

一般按揭計算器只回答「供幾多」，但很多人真正想問的是：

- 我供得起每月幾多？
- 樓價固定下，我至少要準備幾多首期？
- 如果利率或年期改變，我可借到幾多？

因此第一版應直接支援雙模式。

### 7.2 模式設計

#### 模式 A：由首期推月供

輸入已知首期，計算：

- 貸款額
- 每月供款
- 總利息
- 總還款額

#### 模式 B：由目標月供倒推首期

輸入可接受月供，反推：

- 可承受貸款額
- 所需首期
- 首期百分比
- 總利息
- 總還款額

### 7.3 MVP 輸入

模式 A：

- 樓價
- 首期金額
- 年利率
- 還款年期

模式 B：

- 樓價
- 目標月供
- 年利率
- 還款年期
- 可選：按揭成數上限

### 7.4 MVP 輸出

共通輸出：

- 貸款額
- 每月供款
- 總利息
- 總還款額

模式 B 額外輸出：

- 所需首期金額
- 首期佔樓價百分比
- 是否超出成數上限

### 7.5 計算邏輯

第一版採用標準 amortization 模型。

- 月利率 = 年利率 / 12
- 供款期數 = 年期 x 12
- 模式 A：由本金推月供
- 模式 B：由月供反推可承受本金，再倒推首期

### 7.6 第一版刻意不做

- H 按 / P 按切換
- 鎖息上限
- 壓力測試
- 保費、印花稅、律師費
- 現金回贈
- 提前還款情景比較

這些都會快速把工具從「實用 MVP」變成「半個按揭平台」。

### 7.7 驗證規則

- 所有金額必須 >= 0
- 樓價必須 > 0
- 年利率可為 0
- 還款年期必須 > 0
- 首期不可大於樓價

模式 B 額外規則：

- 目標月供必須 > 0
- 若反推出的貸款額大於樓價，顯示「以此月供足以覆蓋全額貸款」
- 若設定按揭成數上限，需顯示是否超出上限

### 7.8 結果呈現重點

模式 B 的主結果不應只是數字，而應是句子：

- `你至少需要準備首期 HK$X`
- `以目前條件，你大約可借 HK$Y`

### 7.9 風險提示

- 結果僅為等額還款估算
- 實際批核取決於銀行、收入、壓測、按揭保險等因素

## 8. 工具三：支票中文英文大寫金額轉換器

### 8.1 使用者問題

用戶想快速把數字金額轉成支票可用格式，避免手動書寫出錯。

### 8.2 工具定位

這是 3 個工具中最明確、最收斂的一個，適合作為第一個落地工具。

### 8.3 MVP 輸入

- 金額

建議支援：

- 整數
- 小數兩位
- 自動格式化逗號

### 8.4 MVP 輸出

- 中文大寫金額
- 英文大寫金額
- 複製按鈕

### 8.5 貨幣範圍

第一版限定：

- 幣種：港幣 HKD
- 小數：最多兩位

### 8.6 格式規則

中文輸出應接近香港支票常見格式，例如：

- `壹仟貳佰叁拾肆圓伍角陸分正`

英文輸出應接近支票常見格式，例如：

- `One Thousand Two Hundred And Thirty-Four Dollars And Fifty-Six Cents Only`

### 8.7 邊界情況

- `0`
- `0.05`
- `1000000`
- `1000000.00`
- `1000000.01`
- 前導零輸入
- 超過兩位小數

### 8.8 驗證與錯誤處理

- 非數字不接受
- 超過兩位小數顯示錯誤
- 金額過大時可設上限，避免超長文案破版

### 8.9 UX 強化點

- 複製中文
- 複製英文
- 一鍵複製全部

## 9. 內容與 i18n 策略

雖然系統已有中英切換，但這組工具第一版應優先確保繁中完整自然，再補英文對應。

### 建議策略

- `zh-HK` 作為主語言
- `en` 提供功能等價翻譯
- 金額格式在不同語言下都保持 `HK$` 標示

### 文案重點

- 香港本地語境優先
- 避免中國內地財經用語
- 避免台灣地產用語

## 10. 技術與實作建議

### 10.1 架構

3 個工具都應採用純前端計算，不依賴 API。

建議結構：

- 頁面：`src/app/(main)/tools/*`
- 共用卡片與頁面片段：`src/components/tools/*`
- 純計算邏輯：`src/lib/tools/*`

### 10.2 推薦拆分

- `src/lib/tools/resignation.ts`
- `src/lib/tools/mortgage.ts`
- `src/lib/tools/cheque-amount.ts`

### 10.3 測試策略

優先測純函式，不先測 UI 細節。

應覆蓋：

- 典型案例
- 零值
- 月尾 / 閏年
- 利率為 0
- 小數位與格式化

## 11. 建議實作順序

### Phase 1

- 首頁 `常用工具` section
- `/tools` hub 頁
- 工具卡資料結構

### Phase 2

- 支票中文英文大寫金額轉換器

### Phase 3

- 按揭計算機

### Phase 4

- 辭職 Last Day 計算機

原因：

- 支票工具最收斂，最容易先建立工具區骨架
- 按揭工具商業價值高，但需求邊界要控制
- 辭職工具規則風險最大，應在文案與假設更清楚後再實作

## 12. Review 重點與待決問題

以下是這份設計文檔中最需要先拍板的地方：

1. `Tools` 是否只作首頁 section + `/tools` hub，還是第一版就加入主導航？
2. 辭職計算機是否只做「按日 / 按月」兩種模式，先不處理更細的勞工法規則？
3. 按揭計算機第一版是否接受只做標準等額還款，不處理 H 按 / 壓測 / 稅費？
4. 支票金額轉換器是否只支援 `HKD`，先不做其他貨幣？
5. 三個工具的排序是否以 `按揭 -> 辭職 -> 支票` 作為首頁預設？

---

## 13. 建議結論

建議把這次需求定義成：

> 在 HKER 首頁新增一個「常用工具」section，並建立一個可擴充的 `/tools` 功能群。第一批上線 3 個香港日常實用工具，其中按揭計算機支援由目標月供反推所需首期。

這樣 scope 清楚、可分階段上線，也不會把首頁變成雜亂的多功能儀表板。
